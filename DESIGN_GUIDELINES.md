# COPENET ENTERPRISE
## Enterprise Design System

---

# OBJETIVO

Todo el sistema debe tener apariencia de un ERP/CRM SaaS moderno.

NO queremos apariencia Bootstrap tradicional.

NO queremos formularios simples.

NO queremos tablas antiguas.

NO queremos pantallas con mucho espacio desperdiciado.

El sistema debe transmitir:

- Enterprise
- SaaS
- Fintech
- Microsoft
- Stripe
- Notion
- Linear
- Hubspot
- Atlassian
- Odoo Enterprise

---

# PRINCIPIOS

Siempre priorizar el contenido.

El usuario debe ver la mayor cantidad de información útil posible.

Toda pantalla debe verse profesional.

Cada pantalla debe sentirse como un producto comercial terminado.

---

# ESPACIADO

Reducir espacios muertos.

Reducir márgenes excesivos.

Reducir altura de headers.

Reducir altura de cards.

Optimizar el uso del espacio vertical.

Las pantallas nunca deben sentirse vacías.

---

# ICONOGRAFÍA

Utilizar únicamente:

Heroicons

o

Lucide Icons

No utilizar iconografía Bootstrap.

Los iconos deben aparecer en:

Cards

Tabs

Headers

Botones

Menús

Breadcrumbs

Tablas

Estados

---

# COLORES

Color principal:

Azul moderno

Secundarios:

Verde
Naranja
Rojo
Morado
Grises

Nunca usar colores saturados.

Toda la interfaz debe ser limpia.

---

# BOTONES

Los botones principales SIEMPRE estarán arriba.

Nunca colocar la acción principal únicamente al final.

Ejemplo:

[Nuevo]

[Guardar]

[Editar]

[Eliminar]

[Exportar]

[Configurar]

siempre visibles.

---

# CARDS

Todas las pantallas estarán compuestas por cards.

Cards con:

bordes redondeados

sombras suaves

padding compacto

espacio uniforme

---

# FORMULARIOS

Los formularios nunca serán una lista vertical enorme.

Agrupar información por bloques.

Ejemplo:

Información General

Configuración Comercial

Configuración Financiera

Configuración Operativa

Configuración FEL

Configuración Contable

Cada bloque dentro de su propia Card.

---

# TABLAS

Las tablas son el componente principal del sistema.

Siempre incluir:

Buscar

Filtros

Ordenamiento

Badges

Paginación

Acciones

No usar tablas Bootstrap básicas.

---

# TABS

No utilizar tabs tradicionales.

Los tabs deben verse como módulos.

Ejemplo:

[ General ]

[ Comercial ]

[ Financiero ]

[ Operación ]

[ Facturación ]

Cada tab con:

icono

estado activo

bordes suaves

animaciones

No usar pestañas Bootstrap.

---

# DASHBOARD

Los dashboards deben contener:

KPIs

Gráficas

Actividad

Alertas

Accesos rápidos

Indicadores

Nunca dejar espacios vacíos.

---

# SIDEBAR

Sidebar tipo SaaS.

Colapsable.

Responsive.

Íconos modernos.

Agrupado por módulos.

Desktop:

Expandido

Tablet:

Colapsado

Mobile:

Hamburguesa

---

# HEADER

Debe contener:

Buscador

Notificaciones

Accesos rápidos

Selector Claro/Oscuro

Usuario

No debe ocupar demasiada altura.

---

# MODO OSCURO

Toda pantalla debe soportar:

Modo Claro

Modo Oscuro

No crear dos diseños.

Utilizar variables de color.

---

# RESPONSIVE

Desktop

Tablet

Mobile

Todo componente debe adaptarse.

---

# UX

Toda pantalla debe responder rápidamente.

Hover

Focus

Animaciones suaves

Microinteracciones

Sin exageraciones.

---

# PANTALLAS

Cada pantalla debe seguir la misma estructura.

Breadcrumb

↓

Título

↓

Descripción

↓

Botones principales

↓

KPIs (si aplica)

↓

Contenido principal

↓

Tablas o formularios

---

# MENÚS

Siempre usar esta jerarquía.

Dashboard

Administración

Cobros

Operación

Reportes

Configuración

Nunca crear menús fuera de esta estructura sin autorización.

---

# DESARROLLO

Antes de crear cualquier pantalla nueva:

1 Analizar este documento.

2 Mantener el mismo estilo.

3 No reinventar el diseño.

4 Todo debe verse parte del mismo producto.

5 Si una pantalla rompe el estándar, corregirla antes de continuar.
